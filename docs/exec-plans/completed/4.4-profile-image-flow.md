# 4.4 — Profile image flow (upload → complete → url → clear)

- Status: completed
- Owner: Core kit maintainers
- Risk: high
- Date: 2026-10-12
- Roadmap: `docs/exec-plans/roadmap.md` Phase 4
- Related ADRs: ADR-0001 (feature tiers), ADR-0004 (engine), ADR-0006 (Redis), ADR-0007 (config)

## Objective

The four profile-image operations in `internal/features/me`, at parity with backend-core-kit `ProfileImageController` / `UserProfileImageService`, plus the platform pieces they need: an object-storage seam with S3 presigning, a per-user/per-IP upload limiter, and a per-route idempotency TTL. Allowlist 18 → 14.

## Ground truth (read from the reference before writing code)

Policy (`profile-image.policy.ts`): allowed `image/jpeg`, `image/png`, `image/webp`; max **5,000,000** bytes; presign TTL **600 s**; get-URL TTL **900 s**. Storage policy: presigned TTL 1..900 s; object keys trimmed, ≤1024 chars, no leading `/`, no NUL, no empty/`.`/`..` segments.

- **upload** (`POST /v1/me/profile-image/upload`, 200, idempotent with the presign TTL, rate-limited, codes `VALIDATION_FAILED, UNAUTHORIZED, RATE_LIMITED, IDEMPOTENCY_IN_PROGRESS, CONFLICT, USERS_OBJECT_STORAGE_NOT_CONFIGURED, INTERNAL`):
  1. DTO validation first (`contentType` trimmed string in the enum; `sizeBytes` int 1..5e6).
  2. Storage disabled → **501** `USERS_OBJECT_STORAGE_NOT_CONFIGURED`.
  3. Service re-checks the content type (issue field `contentType`, message `Allowed: image/jpeg, image/png, image/webp`) and the size (1..max).
  4. `fileId = uuid`, `objectKey = users/<userId>/profile-images/<fileId>`, presign **PUT** with the declared content type, insert a `stored_files` row (`UPLOADING`, bucket, key, type, size, traceId) — user missing/deleted → 401.
  5. Response `{fileId, upload:{method:"PUT", url, headers:{"Content-Type": <type>}}, expiresAt}`; the async expiry job (2 h) is worker territory (5.x).
- **complete** (`POST /v1/me/profile-image/complete`, 204, no idempotency header, codes `…, NOT_FOUND, USERS_OBJECT_STORAGE_NOT_CONFIGURED, USERS_PROFILE_IMAGE_NOT_UPLOADED, USERS_PROFILE_IMAGE_SIZE_MISMATCH, USERS_PROFILE_IMAGE_CONTENT_TYPE_MISMATCH, …`):
  1. Storage disabled → 501; file not found for this owner → **404** `NOT_FOUND` ("File not found").
  2. `DELETED` → 409 `USERS_PROFILE_IMAGE_NOT_UPLOADED` ("Upload is not available"); `ACTIVE` and already attached → 204 (no HEAD).
  3. HEAD the object: missing → 409 `USERS_PROFILE_IMAGE_NOT_UPLOADED`; size or content-type mismatch → best-effort delete + mark `DELETED` → 409 `…_SIZE_MISMATCH` / `…_CONTENT_TYPE_MISMATCH`.
  4. Attach in the repository: mark `ACTIVE` + `uploadedAt`, set `user_profiles.profile_image_file_id`, mark the previous file `DELETED` when one was attached; returns the previous id (cleanup enqueued in the reference).
- **clear** (`DELETE /v1/me/profile-image`, 204, codes `UNAUTHORIZED, INTERNAL`): clear `profile_image_file_id`, mark the file `DELETED`, return the cleared id; no storage gate and idempotent (no image → 204).
- **url** (`GET /v1/me/profile-image/url`, 200 or **204** when unset, codes `UNAUTHORIZED, USERS_OBJECT_STORAGE_NOT_CONFIGURED, INTERNAL`): read the current file **first** (none → 204, even with storage disabled), then 501 when disabled, then presign GET for **900 s**; response `{url, expiresAt}`.
- Rate limiter (`redis-profile-image-upload-rate-limiter.ts`): per-user counters `users:profile-image:upload:user:<id>:requests|blocked` and per-IP (hashed) `…:ip:<hash>:requests|blocked`; block keys short-circuit with `Retry-After`; defaults **user 20/3600 s → block 900 s**, **IP 60/300 s → block 900 s**; disabled Redis passes.
- Schema (Prisma): `StoredFile` (`purpose`, `status UPLOADING|ACTIVE|DELETED`, `bucket`, `objectKey`, `contentType`, `sizeBytes`, `uploadedAt`, `deletedAt`, `traceId`, unique `(bucket, objectKey)`, index `(ownerUserId, createdAt)`), `UserProfile.profileImageFileId` unique, `ON DELETE SET NULL`.
- Mobile client: `createUploadPlan` sends `Idempotency-Key`, PUTs the bytes to the presigned URL with the declared `Content-Type`, then `completeUpload`; the datasource notes complete has no idempotency contract; `clear` sends a key; URL fetch is separate.

## Constraints

- **Storage adapter with no new module dependencies**: `internal/platform/storage` implements SigV4 presigning and signed HEAD/DELETE with the standard library only. Evidence: AWS's published presign example as a unit vector, plus a fake S3 server (`internal/platform/storage/storagetest`) that the feature and contract tests run against.
- **Per-route idempotency TTL**: the upload replay must not hand back an expired presigned URL, so `httpx` gains a TTL-carrying variant; change-password keeps the 24 h default.
- Limiter lives in `me/infra` with the reference's key shapes and six config knobs (`USERS_PROFILE_IMAGE_UPLOAD_*`), following `auth/infra/limiter.go`.
- Object deletion is **best-effort inline** (reject/clear/replace); the durable expiry job (`…_EXPIRE_DELAY_SECONDS`, 2 h) is recorded for 5.x because there is no queue yet.
- Storage config: `STORAGE_S3_ENDPOINT`, `_REGION`, `_BUCKET`, `_ACCESS_KEY_ID`, `_SECRET_ACCESS_KEY`, `_FORCE_PATH_STYLE`; enabled only when all five required values are non-empty (mirrors `ObjectStorageService`).
- `profile_image_file_id` is added by `ALTER TABLE … ADD COLUMN … REFERENCES` (SQLite cannot add a UNIQUE column, so the unique index is separate) plus a `stored_files` table; both engine sets get a 0004 migration.

## Acceptance Criteria

1. Upload with storage disabled → 501; with a fake S3: 200 plan whose URL PUTs the bytes, `method: "PUT"`, header `Content-Type` matching, `expiresAt` = now + 600 s; replay with the same `Idempotency-Key` returns the cached plan with `Idempotency-Replayed: true` and does not mint a second record.
2. Upload validation: unknown content type → 400 field `contentType`; size 0 / >5e6 / non-integer → 400 field `sizeBytes`; rate limit: exceeding the user window → 429 `RATE_LIMITED` with `Retry-After`.
3. Complete: happy path 204 and the profile's image is attached (`ACTIVE`, `uploaded_at` set); wrong size → 409 `…_SIZE_MISMATCH` and the file flips to `DELETED`; wrong content type → 409 `…_CONTENT_TYPE_MISMATCH`; object missing → 409 `…_NOT_UPLOADED`; foreign/unknown file id → 404; repeat after attach → 204.
4. URL: 204 when unset; 200 with a presigned GET after complete; 501 when storage is disabled **and** an image exists; 204 when disabled and unset.
5. Clear: 204, detaches, marks the file `DELETED`, repeat 204; replacing an image marks the previous file `DELETED`.
6. Deleted users → 401 on all four ops.
7. `make verify` green; generated code committed.

## Completion Notes

Deviations and discoveries worth recording: sqlc needed four new `stored_files` timestamp overrides for the sqlite engine (the pg lane inherits `timestamptz`), and `CreateStoredFile` keeps `TraceID` as `interface{}` through the house `NULLIF` pattern. `httpx.IdempotentFor` was added rather than changing `Idempotent`, so change-password keeps the 24 h default while the upload replay expires with the URL it handed out. The contract fixture (`testConfig`) had to carry the limiter defaults: an unset limiter config means `MaxAttempts 0`, which silently never blocks — caught by the 429 test and fixed by seeding production defaults in the fixture. Object-store deletion is inline best-effort; the reference enqueues it, and the durable expiry job (2 h) lands with the worker.

Review round 1 fixes (both applied): the pg migration now declares `size_bytes BIGINT` so both engines generate `int64` (a plain `INTEGER` is 32-bit on Postgres and would have produced engine-divergent types against the `int64` domain/ports); and `UploadLimitConfig` moved to the feature root (`me.Deps`) with a conversion inside `Register`, so `cmd/api` no longer imports `me/infra`.
