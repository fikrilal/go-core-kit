- Status: completed

- Related ADRs: ADR-0002 (contract parity), ADR-0003 (stdlib HTTP with platform middleware), ADR-0009 (observability)

## Objective

Implement `internal/platform/httpx`: the router with the standard middleware chain (request id → access logging → panic recovery), envelope response helpers, the central RFC7807 problem mapper, and typed global error codes. All contract-visible HTTP behavior is owned here.

## Constraints

- stdlib `net/http` only, plus `github.com/google/uuid` for generated request ids.
- Contract shapes are fixed by backend-core-kit: envelope `{data, meta?}`, problem details with `code` + `traceId`, `X-Request-Id` echoed on every response, `Retry-After` for 429.
- No framework; features must not re-implement any of this (helpers are the only sanctioned writers).
- Scope: router + middleware + helpers + problem mapping + codes. No real endpoints yet (bootstrap is 1.10), no OTel field yet.

## Impact Areas

- API / contract: yes (envelope, problem details, headers)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: yes (access log entries with correlation)
- CI / release: no

## Acceptance Criteria

1. `NewRouter` applies request-id → access-log → recover over Go 1.22 pattern routes; `X-Request-Id` is accepted, generated when missing, and echoed on every response.
2. Envelope helpers: `Data` (200 `{data}`), `List` (200 `{data, meta}` with typed `ListMeta`), `Created` (201 + `Location`), `NoContent` (204, no body).
3. Problem mapping: `ProblemError` → RFC7807 with `type`, `title`, `status`, `detail?`, `code`, `traceId`, `errors[]?`, and `Retry-After` when set; unknown errors → 500 `INTERNAL` with no leaked detail, logged with the original error.
4. Unmatched routes return problem-details 404 `NOT_FOUND` (not the stdlib plain-text default).
5. Panics produce a 500 problem response and are logged with stack.
6. Access log entries carry method, path, status, duration, and request id; 5xx entries log at error level.
7. Tests cover all of the above; `make verify` green.

## Decision Log

- 2026-10-10: Unmatched routes are served by a catch-all `/` handler that returns problem-details 404, because the stdlib default (`404 page not found` plain text) violates the contract.
- 2026-10-10: Unexpected (non-`ProblemError`) failures are logged with the original error but rendered as a bare 500 `INTERNAL` — details never leak to clients.
- 2026-10-10: Request ids use UUID v4 (`google/uuid`); UUID v7 stays reserved for persisted record ids.
- 2026-10-10: `otelTraceId` is intentionally absent until the otel module lands (contract field is optional).
