# 2.2 — Generate contract types

- Status: completed
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 2.2
- Related ADRs: ADR-0002 (parity), ADR-0010 (single verify gate)

## Objective

Generate Go request/response types from the pinned snapshot with `oapi-codegen` (types only, handlers stay hand-written), commit them, and extend `make generate` + the drift gate so stale types fail `make verify`.

## Constraints

- `oapi-codegen` v2.8.0 pinned in the Makefile and installed by `make tools` (GOBIN → `$HOME/.local/bin`, like the other tools).
- Config `oapi-codegen.yaml` at the root (sibling of `sqlc.yaml`); output `contracts/generated.go`, package `contracts`, models only, `skip-prune: true` so every component schema is generated.
- Generated code is committed and byte-stable: the drift step regenerates and fails on any unstaged diff (existing sqlc drift pattern, extended).
- `doctor` grows to verify `oapi-codegen` against the Makefile pin.
- Handlers import contract types; no server-interface generation (ADK-0002 decision).

## Impact Areas

- API / contract: yes (typed handlers)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: no
- CI / release: yes (tools install + drift scope)

## Acceptance Criteria

1. `contracts/generated.go` committed, compiles, and contains the operation/component types (spot-checked against the snapshot).
2. `gokit contract generate` runs `oapi-codegen` and fails with a `make tools` hint when the tool is missing.
3. `make generate` regenerates both sqlc and contract artifacts; the drift step covers `contracts/generated.go`.
4. `doctor` reports `oapi-codegen` against the pin; `make tools` installs it; CI installs it.
5. Drift honesty: touching a generated file fails `make verify`'s drift step.

## Decision Log

- 2026-10-10: Types-only generation keeps handlers readable and diff-friendly (rejected: full server interface generation — rigid).
- 2026-10-10: `skip-prune` keeps unused component schemas so future features can adopt contract types without regenerating.
- 2026-10-10: Drift covers both generators in one step; `make generate` is the single regenerate command.
- 2026-10-10: Drift is strict: any committed-state difference counts — modified, deleted, and untracked generated files. Review round 1 closed the untracked blind spot (a missing generated file must not pass CI silently); an uncommitted batch is red at the drift step until committed, by design.
- 2026-10-10: `make drift` and the verify drift step run the same gokit implementation (`gokit drift check`) — one source, no shell divergence.

## Completion Notes

Generated types depend on `github.com/oapi-codegen/runtime` (formats such as UUID/date-time). The unit test (`TestContractGenerateIsDeterministic`) skips with a `make tools` hint when the generator is absent and otherwise asserts byte-stable output; the committed-state assertion lives in the drift gate itself. Fix during the task: `oapi-codegen --version` prints two lines (module path + version), so the doctor version pattern became multiline — shared with sqlc. Review round 1: drift strictness settled (untracked generated files are drift) and the `drift` entry point is single-sourced in gokit.
