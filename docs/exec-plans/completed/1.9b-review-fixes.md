## Objective

Close the three blocking findings from the automated review of 1.9b. All were verified empirically before fixing; the high finding was reproduced exactly as reported.

## Findings to fixes

1. **[High] Stale scratch resurrects deleted query files.** `sqlc generate` does not prune its output directories, and `gokit db generate` copied every file found in `.gen/` — a planted stale file was reproduced surviving into `internal/db/gen`. Fix: `os.RemoveAll(scratchDir)` before running sqlc, so each run builds from a clean scratch.
2. **[Medium] `make tools` breaks on macOS.** The sqlc download URL hardcoded `_linux_`; the darwin asset exists for the pinned version (verified), so the fix detects `uname -s` and stays cross-platform.
3. **[Low] No automated compile gate for the `pg` lane.** `make verify` now includes `build-pg` (`go build -tags pg ./internal/db/gen`), so a Postgres-incompatible query or override mismatch fails CI, not phase 7.

## Steps

- [x] Clean scratch before generation + reproduce/verify the stale-file scenario
- [x] OS-aware sqlc download in `make tools`
- [x] `build-pg` in the verify gate
- [x] Full re-verification (verify, determinism, stale probe)
