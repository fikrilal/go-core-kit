# 1.10 — API Bootstrap

- Status: completed
- Owner: Core kit maintainers
- Risk: medium (process lifecycle, graceful shutdown)
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 1.10
- Related ADRs: ADR-0001 (composition roots only), ADR-0003 (stdlib HTTP), ADR-0009 (observability)

## Objective

Ship `cmd/api`: the composition root that loads config, builds the platform handles (SQLite + migrations at boot, Redis), assembles the router (idempotency enabled) with `database` + `redis` readiness checks, and serves with graceful shutdown on SIGINT/SIGTERM. Also lands the request-body cap that the 1.4 follow-up scheduled for this task.

## Constraints

- Composition root only: wiring, lifecycle, and startup/shutdown logs — no business logic.
- `main()` stays thin; `run`/`serve` take explicit dependencies so the serving path is testable over real HTTP without process control.
- Shutdown uses `context.WithoutCancel` — the signal context is already cancelled when shutdown starts, so the drain window must detach from it.
- `cmd/api` is build-tagged `!pg` until the Postgres engine lands (7.1): the `pg` build skips database-dependent binaries instead of failing.
- Body cap: 1 MiB, enforced in the platform chain before handlers; oversized bodies surface as the existing decode failure (400 `VALIDATION_FAILED`). A 413 mapping is deferred until the contract snapshot lands (2.3) rather than inventing an error code.

## Impact Areas

- API / contract: yes (process entrypoint; no route surface change)
- DB / migrations: yes (migrations applied at boot)
- Auth / session: no
- Queue / jobs: no (worker bootstrap is phase 5)
- Config / secrets: yes (first real consumer of `Load`)
- Observability: yes (startup/shutdown/exit logs)
- CI / release: yes (`build-pg` widens to `./...`)

## Acceptance Criteria

1. `run` wires: config → logger → SQLite (migrated) → Redis → router with idempotency → health checks (`database`, `redis`) → HTTP server with `ReadHeaderTimeout`.
2. Graceful shutdown: SIGINT/SIGTERM drains within 10 s; `serve` returns nil on shutdown and a wrapped error otherwise.
3. Requests over 1 MiB fail in the platform chain (400) before handler logic; under-limit requests are untouched.
4. Smoke test over real HTTP: `/health` 200, `/ready` 200, `/ready` 503 when a dependency fails (miniredis `SetError`), then clean shutdown.
5. `go build -tags pg ./...` passes with `cmd/api` skipped by tag; `make verify` green.

## Decision Log

- 2026-10-10: `serve` takes an explicit `net.Listener` so tests can bind port 0 and assert real HTTP behavior; production passes the configured port.
- 2026-10-10: Shutdown context uses `context.WithoutCancel(ctx)` — the parent is cancelled by definition when this path runs.
- 2026-10-10: db/redis handles opened with error-returning `Open` (not `MustOpen`) in `run`; `MustOpen` remains for tests.
- 2026-10-10: The `!pg` tag on `cmd/api` keeps the pg lane compiling (skipping db-dependent binaries) until 7.1 provides the engine.
- 2026-10-10: The cmd/api smoke test uses a dedicated client with keep-alives disabled. Under repeated runs the shared `http.DefaultClient`'s pooled connections could leave a half-read request on a fresh server, holding `Shutdown` until `ReadHeaderTimeout` — the same order as the test's 5 s wait. The deterministic client removed the flake (800 hammer iterations clean); production budgets stay sound (10 s shutdown budget > 5 s read-header timeout).
- 2026-10-10: go-redis's internal logger is silenced inside `platform/redis` — failures surface through wrapped errors and readiness checks so logging stays one structured pipeline (observed as stray pool lines during the live boot).

## Completion Notes

Shipped `cmd/api` end to end: `runMain`/`run` wire config → logger → SQLite (migrated at boot) → Redis → idempotency-enabled router with `database` + `redis` readiness checks → HTTP server (`ReadHeaderTimeout`), with `serve` handling SIGINT/SIGTERM, draining via `context.WithoutCancel` inside a 10 s budget. The 1.4 follow-up landed too: a 1 MiB body cap sits in the platform chain (400 on oversize; 413 mapping deferred to the contract snapshot). Gate-driven fixes during the task: `exitAfterDefer` avoided via `runMain() int`, `net.ListenConfig` for context-aware listening, wrapped platform errors, and the go-redis logger silenced. The shutdown smoke test's flake was root-caused (shared client pooling → half-read request holding Shutdown until `ReadHeaderTimeout`) and eliminated with a deterministic client, verified over 800 iterations.
