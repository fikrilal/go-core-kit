## Objective

Land the sqlc pipeline: dual-engine `sqlc.yaml`, the first portable-subset queries, the build-tag-selected generated package at `internal/db/gen`, the `gokit db generate` tool, and the drift gate wired into CI.

## Constraints

- Shared queries use named args only (`sqlc.arg`) so one file parses for both engines; portable subset rules apply (no `$1`/`?` literals, no engine-only constructs).
- Generated output is committed; build tags are injected by our tool (`//go:build !pg` / `//go:build pg`), one `package gen` in one directory.
- Both engines' generated code must expose identical Go signatures: timestamp columns map to `utctime.Time` via overrides on sqlite (`TEXT` + column) and postgres (`timestamptz`).
- Postgres output uses the `database/sql` package (no `pgx` yet — the phase-7 driver must fit the same surface).
- `.gen/` is sqlc scratch space: gitignored, invisible to Go tooling (dot-directory).

## Acceptance Criteria

1. `sqlc.yaml` parses two blocks over the same `db/queries/common` set; generation succeeds for both engines.
2. `gokit db generate` regenerates `internal/db/gen` deterministically: sorted files, engine-prefixed names, build tags, stale files removed (unit-tested pure pieces).
3. Generated code compiles under the default build and under `-tags pg`; the sqlite lane passes an end-to-end round trip (`CreateUser`/`GetUserByID` via `gen.New`, including `sql.ErrNoRows`).
4. `make generate` and `make drift` exist; CI installs the pinned sqlc and runs the drift step.
5. `make verify` green; generated files do not trip formatters or linters.

## Decision Log

- 2026-10-10: sqlite timestamp overrides use table-qualified column names (`users.created_at`, `users.updated_at`) — sqlc requires `tablename.colname` and rejects combining `column` with `db_type`. New timestamp columns therefore add one reviewable entry per sqlite table; the Postgres block maps all `timestamptz` columns in one rule. The asymmetry is inherent to SQLite's type system (every TEXT column is indistinguishable); the `-tags pg` build keeps the two lanes' signatures honest.
- 2026-10-10: The generated package lives in one directory with disjoint build-tag files — `gen.New(...)` and all query types read identically in both builds.
- 2026-10-10: `.gen/` scratch output stays on disk for debugging; it is gitignored and dot-prefixed so Go tooling ignores it.

## Completion Notes

Shipped the pipeline end to end: dual-engine `sqlc.yaml` over the shared portable queries (`CreateUser` with `RETURNING`, `GetUserByID`), generated code packaged by `gokit db generate` into `internal/db/gen` (sorted, engine-prefixed, build-tagged, stale files removed — both pure helpers unit-tested), and the drift gate (`make drift`) wired into CI with a pinned sqlc v1.31.1. Both engines generate identical Go signatures (`utctime.Time` timestamps); the generated `gen.New(...)` round trip (create → fetch → `sql.ErrNoRows`) runs green on the sqlite lane. Lint adaptations kept the bar: `context.Background` for `CommandContext`, and two justified `gosec` nolints on the tool's own scratch-file plumbing. sqlc v1.31 override rules were learned the hard way (no `column`+`db_type` combination; `column` needs `tablename.colname`) and are recorded in the decision log.
