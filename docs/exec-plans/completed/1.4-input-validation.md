# 1.4 — Input Validation

- Status: active
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 1.4
- Related ADRs: ADR-0002 (contract parity), ADR-0003 (stdlib HTTP with platform middleware)

## Objective

Add `httpx.Decode` to the platform HTTP package: JSON body decoding plus `validator/v10` struct validation, mapped to the contract error shape `errors[] {field, message}` with `VALIDATION_FAILED`.

## Constraints

- New dependency: `github.com/go-playground/validator/v10` only.
- `Decode` does not write responses; rendering stays with `WriteError` (single responsibility).
- Field names in `errors[]` use the struct's `json` tag names, not Go field names.
- Unknown JSON fields and trailing data are rejected (parity with backend-core-kit's whitelist + forbid-unknown behavior).
- Validation messages come from a small explicit tag map; internals are never leaked.

## Impact Areas

- API / contract: yes (validation error shape)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: no
- CI / release: no

## Acceptance Criteria

1. `Decode(r, v)` parses a JSON body into `v`, rejects unknown fields and trailing data with 400 `VALIDATION_FAILED`.
2. Struct validation returns **all** field failures as `errors[] {field, message}` using `json` tag names.
3. Valid input returns `nil`.
4. Tests cover: valid payload, missing required field, invalid email, multiple failures, malformed JSON, unknown field, trailing data, and the full problem response shape through a handler.
5. `make verify` green.
