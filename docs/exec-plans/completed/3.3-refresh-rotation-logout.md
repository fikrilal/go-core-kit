# 3.3 — Refresh rotation, reuse detection, logout

- Status: completed
- Owner: Core kit maintainers
- Risk: high
- Date: 2026-10-11
- Roadmap: `docs/exec-plans/roadmap.md` task 3.3
- Related ADRs: ADR-0002 (parity)

## Objective

Ship `auth.refresh` and `auth.logout` wire-identical to backend-core-kit: rotating refresh tokens with replay (reuse) containment, session-family revocation, and 204 logout.

## Reference (backend-core-kit, exact behaviors)

- **Refresh flow**: hash the presented token → load token+session+user; deleted → 401 `AUTH_REFRESH_TOKEN_INVALID`; suspended → 403; session revoked → 401 `AUTH_SESSION_REVOKED`; token or session expired → 401 `AUTH_REFRESH_TOKEN_EXPIRED`; token already revoked or replaced → revoke the session family and return 401 `AUTH_REFRESH_TOKEN_REUSED`.
- **Mint-before-rotate**: the access token is signed before rotation so non-2xx refresh responses never consume the caller's refresh token.
- **Rotation transaction**: insert the next token with the *previous* token's expiry; mark the old token revoked with `replaced_by_id` guarded by `revoked_at IS NULL AND replaced_by_id IS NULL`; losing that race also revokes the family and reports reuse; then touch the session (`last_seen_at`, and `ip`/`user_agent` when provided).
- **Family revocation**: clear `active_key` and push fields, set `revoked_at` when unset, revoke all session refresh tokens when unset.
- **Logout**: revoke by refresh-token hash; unknown token → 401 `AUTH_REFRESH_TOKEN_INVALID`; success → **204**.
- **Wire**: refresh returns `AuthResultEnvelopeDto` with `AuthUserDto` (id/email/emailVerified, `authMethods` omitted); logout has no body.

## Constraints

- Refresh has no rate limiter (not in the snapshot's declared codes); neither operation is idempotency-wrapped.
- Family revocation runs inside one transaction (single-connection SQLite — no nested `InTx`).
- Feature code stays free of `database/sql`; nullable columns are read through generated types only.
- The refresh response must omit `authMethods` — assert absence in tests, not just nil.

## Verification

```bash
go test ./cmd/api/... -run Contract -count=1 -v
go test ./internal/features/auth/... -count=1
make verify
```

Outcome: `auth.refresh` rotates with the reference semantics — happy rotation validates against `AuthResultEnvelopeDto` (raw-JSON assertion proves `authMethods` is omitted), the old token is revoked with `replaced_by_id` pointing at the successor, and the session is touched. Reuse contains the session family: the presented token returns 401 `AUTH_REFRESH_TOKEN_REUSED` and the successor immediately reports 401 `AUTH_SESSION_REVOKED`. Expired, invalid, session-revoked, suspended, and deleted paths all map to their exact codes. `auth.logout` returns 204 with an empty body, revokes the session and every refresh token (refresh after logout → `AUTH_SESSION_REVOKED`), is idempotent on repeat, and returns `AUTH_REFRESH_TOKEN_INVALID` for unknown tokens. Unit tests cover the kind mapping, mint-before-rotate ordering (the access token is signed before the failing rotation), reuse containment, and logout outcomes. Coverage: 6 implemented / 28 allowlisted / 34 declared. Race-clean; `make verify` green except drift-until-commit.

## Completion Notes

`GetRefreshTokenWithSession` keeps the sqlc column overrides through aliases (all timestamps come back as `utctime.Time`), so the repository reads nullable columns as zero/`Valid` without touching `database/sql`. The refresh response type is `contracts.AuthResultDto` (no roles, no profile) — distinct from register/login's `AuthResultWithMeDto`, mirroring the reference exactly. The rotation transaction delegates its decision tree to `rotateExisting`; the wire error-code constants carry justified `gosec` G101 nolints.
