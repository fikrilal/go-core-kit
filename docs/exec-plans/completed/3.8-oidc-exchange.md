# 3.8 — OIDC exchange

- Status: completed
- Owner: Core kit maintainers
- Risk: high
- Date: 2026-10-11
- Roadmap: `docs/exec-plans/roadmap.md` task 3.8
- Related ADRs: ADR-0002 (parity)

## Objective

Ship `auth.oidc.exchange` wire-identical to backend-core-kit: verify a Google ID token, resolve or create the user through an external identity (never auto-linking by email), mark new users verified, attach profile names from the token, and issue a first-party session with a full Me response.

## Reference (backend-core-kit, exact behaviors)

- **Verification port**: kinds `verified` / `invalid` / `not_configured`; only `GOOGLE`; client ids from `AUTH_OIDC_GOOGLE_CLIENT_IDS` (comma-separated); JWKS `https://www.googleapis.com/oauth2/v3/certs`; issuers `https://accounts.google.com` and `accounts.google.com`; `email_verified` accepts boolean or `"true"`/`"false"` strings; `name`/`given_name`/`family_name` carried when present.
- **Service order**: verify (not_configured → 500 `AUTH_OIDC_NOT_CONFIGURED`; invalid → 401 `AUTH_OIDC_TOKEN_INVALID`; unverified email → 400 `AUTH_OIDC_EMAIL_NOT_VERIFIED`) → find by (provider, subject) → else email collision → 409 `AUTH_OIDC_LINK_REQUIRED` ("We found an existing account for this email. Sign in with your password to link Google sign-in.") → else create user (`email_verified_at = now`) + profile (only non-empty names) + identity in one transaction; identity uniqueness races re-fetch the winner. Deleted → masked 401 `AUTH_INVALID_CREDENTIALS` (upstream emits a code outside its declared set — mirrored, see Decision Log); suspended → 403 `AUTH_USER_SUSPENDED`. Then session issuance + `getMe`.
- **Response**: `AuthResultWithMeEnvelopeDto`; new users carry `authMethods: ["GOOGLE"]`, `emailVerified: true`, and token-sourced profile names.

## Constraints

- New tables mirror the reference model: `external_identities` (unique `(provider, subject)` and `(user_id, provider)`) and `user_profiles` (profile image columns land with 4.4).
- Me responses route through one `MeView` (user + profile + auth methods) for register, login, and exchange — mirroring the reference's controller-level `getMe`.
- Google ID-token verification is an adapter over the platform clock (no `time.Now`), with an injectable JWKS URL for tests; JWKS fetched with a TTL cache.
- Client-id configuration stays in platform config (`AUTH_OIDC_GOOGLE_CLIENT_IDS`); staging/production behavior mirrors the reference (empty ids → `not_configured` → 500).

## Acceptance Criteria

1. Live exchange: new Google user → 200 validated against the snapshot with `authMethods: ["GOOGLE"]`, `emailVerified: true`, profile names, verified access token, issued session; second exchange for the same identity reuses the user.
2. Email collision with an existing password account → 409 `AUTH_OIDC_LINK_REQUIRED` (no auto-link, user count unchanged); identity uniqueness race covered by repository tests.
3. Problem paths with declared codes: not configured → 500 `AUTH_OIDC_NOT_CONFIGURED`; bad signature/audience/issuer/expiry → 401 `AUTH_OIDC_TOKEN_INVALID`; `email_verified: false` → 400 `AUTH_OIDC_EMAIL_NOT_VERIFIED`; unknown provider → 400 `VALIDATION_FAILED`; suspended → 403.
4. Verifier adapter unit tests (jwks via httptest): kinds, issuer/audience/expiry checks, string `email_verified`, name fields, non-GOOGLE provider.
5. `make verify` green.

## Verification

```bash
go test ./internal/features/auth/... -count=1 -v
go test ./cmd/api/... -run "Oidc" -count=1 -v
make verify
```

Outcome: `auth.oidc.exchange` is live against a JWKS-backed Google token fixture — a new identity creates the verified user, profile row, and external identity in one transaction and returns the snapshot-validated Me response with `authMethods: ["GOOGLE"]`, `emailVerified: true`, token-sourced profile names, and a verifiable access token; a repeated exchange reuses the user (1 user / 1 identity / 2 sessions). Email collisions with a password account return 409 `AUTH_OIDC_LINK_REQUIRED` with no identity created. Failures asserted with declared codes: tampered/expired/wrong-audience tokens → 401 `AUTH_OIDC_TOKEN_INVALID`, unverified email → 400 `AUTH_OIDC_EMAIL_NOT_VERIFIED`, unknown provider and missing fields → 400 `VALIDATION_FAILED`, suspended → 403, unconfigured client ids → 500 `AUTH_OIDC_NOT_CONFIGURED`. Verifier adapter tests cover the kinds, JWKS caching (one fetch), string `email_verified`, unknown providers, and fail-closed JWKS outages. Coverage: 9 implemented / 25 allowlisted / 34 declared. Race-clean; `make verify` green except drift-until-commit.

## Completion Notes

Three platform seams absorbed the depguard boundary: the verifier reads claims through jwx's `jwt` API (no `encoding/json` in features), the JWKS fetch uses the TTL cache keyed by the platform clock, and `httpx.Document` stayed the only non-enveloped path. Register and login now build their Me responses through the same `MeView` as exchange, so profile names and auth methods come from one query path; `Result` keeps the user core because refresh's `AuthUserDto` deliberately skips Me. Gate-driven fixes: sqlc alias/ambiguity resolution, jwt v3 getter shapes, nilerr nolints for the kind-based failure mapping, and the migration round-trip test now rolls back both post-skeleton migrations.
