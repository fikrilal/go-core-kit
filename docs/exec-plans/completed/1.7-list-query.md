# 1.7 — List Query Parser

- Status: completed

## Objective

Add the list-query parser to `httpx`: `limit`, `cursor`, `sort`, `filter[...]`, and `q` parsing with per-endpoint allowlists, returning the contract `ListQuery` or a 400 `VALIDATION_FAILED` with `errors[]`.

## Constraints

- stdlib only.
- Wire format follows the backend-core-kit standard: `limit` (default 25, default max 250), opaque `cursor`, `sort` with `-` prefix and max 3 fields, `filter[field]` / `filter[field][op]` with comma-separated `in` lists only (no repeated params), per-endpoint allowlists only.
- Parsing only: cursor encode/decode and SQL building belong to repositories.
- Error list order is deterministic (sorted parameter scan).
- Contract error shape only — the parser never writes responses.

## Impact Areas

- API / contract: yes (list request semantics)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: no
- CI / release: no

## Acceptance Criteria

1. `ParseListQuery(r, cfg)` returns `ListQuery` with defaults applied (`limit` 25 / min 1 / cfg max, default sort cloned from config).
2. `sort` parses `-field` descending, enforce allowlist and max 3 fields; empty `sort` falls back to the configured default.
3. Filters parse `filter[field]`, `filter[field][eq|in|gte|lte]` into `map[field]map[op][]values`; only configured fields and ops are accepted; repeated parameters are rejected.
4. Unknown or malformed `filter[...]` keys, out-of-range `limit`, unsupported `q`, and bad sort fields accumulate into a single 400 `VALIDATION_FAILED` with `errors[] {field, message}`.
5. Tests cover defaults, full parse, each failure class, accumulation, and a handler-level response shape; `make verify` green.

## Decision Log

- 2026-10-10: Filters are typed as `map[string]map[FilterOp][]string` — direct addressing per field and operator (a field can carry both `gte` and `lte`).
- 2026-10-10: Empty-valued parameters (`sort=`, `cursor=`) are treated as absent; malformed non-empty values are strict errors.
- 2026-10-10: Filter-shaped keys that do not match the grammar (`filter[status]x`) are rejected rather than ignored, mirroring the strict decode behavior from 1.4.
- 2026-10-10: Cursor codec is not built here — repositories own cursor shape when the first paged query lands.
