# 4.2 — Sessions list/revoke

- Status: completed
- Owner: Core kit maintainers
- Risk: medium
- Date: 2026-10-12
- Roadmap: `docs/exec-plans/roadmap.md` Phase 4
- Related ADRs: ADR-0003 (HTTP behavior), ADR-0005 (portable SQL), ADR-0006 (Redis)

## Objective

`users.me.sessions.list` + `users.me.sessions.revoke` in `internal/features/me`, at parity with backend-core-kit `MeSessionsController` / `AuthSessionsService`. This is the first paged endpoint: build the cursor codec that plan 1.7 deferred ("when the first repository pagination lands"). Allowlist 22 → 20.

## Ground truth (read from the reference before writing code)

- **List**: `requireExistingNonDeletedUser` first (401). Returns **all** sessions (active, revoked, expired), newest first. Item: id, deviceId, deviceName, ip, userAgent, lastSeenAt, createdAt, expiresAt, revokedAt (null), `current` (= principal session id), `status` = `revoked` when `revokedAt != null`, else `expired` when `expiresAt <= now`, else `active`. Query: default limit 25 / max 100, sort allowed `createdAt`/`id`, default `-createdAt`, **tie-breaker id DESC**, no filters, no search. Page = `limit + 1` rows; `hasMore` from the extra row; `nextCursor` from the last kept row.
- **Cursor**: opaque, `{v: 1, sort: normalizedSort, after: {field: value}}` base64; the repo builds the keyset predicate from the cursor's `after` values. Snapshot example decodes exactly that shape.
- **Revoke**: `POST /v1/me/sessions/{sessionId}/revoke`, path param is a **UUID** (`@IsUUID()` → 400 `VALIDATION_FAILED`). `requireExistingNonDeletedUser` first (401 before 404). Unknown id or another user's session → 404 `NOT_FOUND` ("Session not found"). Already-revoked → still 204 (device/push state re-cleared, refresh tokens re-revoked). Always: clear `active_key` + push columns (`push_token_updated_at`/`push_token_revoked_at` = now), set `revoked_at` only when null, revoke the session's refresh tokens where still null. No `Idempotency-Key` header on this op.
- Snapshot codes: list `VALIDATION_FAILED, UNAUTHORIZED, INTERNAL`; revoke `VALIDATION_FAILED, UNAUTHORIZED, NOT_FOUND, INTERNAL`.

## Constraints

- Cursor codec lands in `httpx` (platform list machinery, matching the deferred 1.7 follow-up): version-tagged, base64url, opaque, and rejecting a cursor built for a different sort.
- Keyset SQL stays in the repository (allowed: "SQL lives in repository code and db/queries"). The sort set is open enough (1–3 fields over `createdAt`/`id`) that static sqlc variants would repeat the projection four-plus times; the repo assembles the predicate from a constant projection + explicit sort handling. The repo file is `//go:build !pg`, so `?` placeholders are correct here.
- `utctime.Time` gains `Stored()` so the cursor carries the exact database text form (`Value` reuses it) — byte-wise `TEXT` comparison is what keeps keyset pages chronological.
- Revoke reuses the existing queries: `ClearSessionDeviceState`, `RevokeSession` (`revoked_at IS NULL` guard = the not-yet-revoked branch), `RevokeSessionRefreshTokens`.
- No new sqlc queries: `GetUserStatus` (users.sql) serves the deleted check; no `make generate` drift expected.
- Sort/status policy lives in `app` (status computation, `current` flag, cursor-to-view mapping is wire); the repo returns stored rows only. Ports stay framework-free: the app converts the wire `httpx.ListQuery` into port sort fields.

## Acceptance Criteria

1. `GET /v1/me/sessions` returns the envelope with `{data, meta{limit, hasMore, nextCursor?}}`, newest first by default, `current` on the caller's session, statuses derived from `revokedAt`/`expiresAt`.
2. `limit=1` paginates: `hasMore: true`, `nextCursor` present, the next page returns the remaining session with no overlap; a malformed cursor, a cursor for another sort, or an unknown sort field is 400 `VALIDATION_FAILED`; limit bounds and non-integer limits are 400.
3. `POST /v1/me/sessions/{sessionId}/revoke` returns 204 and revokes the session and its refresh tokens (refresh with that token afterwards is 401 `AUTH_SESSION_REVOKED`); repeats stay 204; unknown or foreign ids are 404 `NOT_FOUND`; a non-UUID id is 400; missing/deleted users are 401.
4. `sort=id`, `sort=createdAt`, and descending variants behave (ordering asserted on ids).
5. `make verify` green; no generated drift.

## Completion Notes

One deviation from the plan's "no new sqlc queries": the owner check needs a session-by-id read, so `GetUserSession` was added to `me.sql` (id, user_id, revoked_at) and regeneration followed. Revoke reuses `RevokeSession` (its `revoked_at IS NULL` guard is exactly the reference's not-yet-revoked branch), `ClearSessionDeviceState`, and `RevokeSessionRefreshTokens`.

The list is the first hand-written repository query: sqlc cannot express the keyset variants without repeating the projection, so the repository assembles `projection + predicate + ORDER BY + LIMIT` from constants, with `?` placeholders correct for this `//go:build !pg` file. Nullable scans use `*string` (no `database/sql` import in features) and `utctime.Time` treats NULL as zero. The cursor codec landed in `httpx`, closing the 1.7 follow-up.
