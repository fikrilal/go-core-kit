- Status: completed

- Risk: low

- Related ADRs: ADR-0010 (single verify gate); roadmap harness section (drift & docs checks)

## Objective

Add `gokit knowledge check` with four mechanical checks — `env.example` ↔ config schema, the AGENTS.md project map ↔ actual directories, markdown link integrity, and ADR index completeness — running first in the fast profile so `make verify` covers them.

## Constraints

- Read-only, runs from the repository root, sub-second.
- Planned-but-not-yet-created paths are explicit, shrinking allowlists in code: `cmd/worker/`, `internal/features/`, `internal/shared/`, `contracts/` (AGENTS.md map) and the `contracts/` backtick reference in `docs/README.md`.
- AGENTS.md gains a `docs/` line in its architecture map — it is part of the repo architecture and the reverse direction of the map check requires it.
- Link checking covers local markdown links in `docs/**`, AGENTS.md, and README.md, plus backticked repo paths in the two index files (`docs/README.md`, `docs/adr/README.md`).

## Impact Areas

- API / contract: no
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: yes (env.example ↔ schema drift)
- Observability: no
- CI / release: yes (runs inside `make verify`)

## Acceptance Criteria

1. Env check: every `env` tag in `config.Config` is documented in `env.example` and every documented key exists in the schema (reflection-based, bidirectional).
2. Project map: every non-planned AGENTS.md map entry exists on disk; the top-level directories (`cmd`, `internal`, `db`, `tools`, `docs`) appear in the map.
3. Links: local markdown links resolve; backticked repo paths in the index files resolve (planned allowlist aside).
4. ADR index: every `NNNN-*.md` file is listed in `docs/adr/README.md` and every index link resolves.
5. Checks pass on the current tree; unit tests cover the parsers and link checker with temp fixtures; `make verify` green.
