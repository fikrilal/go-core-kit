# 3.2 — Password register and login

- Status: completed
- Owner: Core kit maintainers
- Risk: high
- Date: 2026-10-11
- Roadmap: `docs/exec-plans/roadmap.md` task 3.2
- Related ADRs: ADR-0002 (parity), ADR-0018-style feature tiers (`docs/core/project-architecture.md`)

## Objective

Ship `auth.password.register` and `auth.password.login` wire-identical to backend-core-kit: argon2id credentials, dummy-hash timing equalization, Redis login rate limiting with `Retry-After`, first-party sessions with EdDSA access tokens and hashed refresh tokens. Contract suite green; the allowlist shrinks to 30.

## Reference (backend-core-kit, exact behaviors)

- **Normalization**: `email.trim().toLowerCase()`; password policy min length 10 (register), 1 (login).
- **Argon2id**: `@node-rs/argon2` defaults — m=19456 KiB, t=2, p=1, 32-byte hash, PHC string; dummy hash computed once for unknown emails.
- **Errors**: `AUTH_EMAIL_ALREADY_EXISTS` 409, `AUTH_INVALID_CREDENTIALS` 401, `AUTH_USER_SUSPENDED` 403, `RATE_LIMITED` 429 + `Retry-After`, `VALIDATION_FAILED` 400 with `errors[]`; deleted users and unknown emails return invalid-credentials (masked).
- **Login limiter**: keys `auth:login:email:<sha256-b64url(email)>:{failures,blocked}` and the ip twin; INCR with window expiry (60s), block set at 10 failures for 900s; block checked before lookup; counters cleared on success; `Retry-After` = block TTL.
- **Session issuance**: refresh token = 32 random bytes base64url, stored as sha256 base64url; session expires = now + 30d; `activeKey = userId:deviceId` revokes the previous session for the device; refresh token expires with the session.
- **Access token**: EdDSA JWT, header `{alg, kid, typ: JWT}`, claims `sub, sid, email_verified, roles, typ:"access", iat, exp (+900s), jti, iss?, aud?`.
- **Keyring**: `AUTH_SIGNING_KEYS_JSON`/`_BASE64` JWK set; staging/production require keys; non-production generates an ephemeral key.
- **Response**: `{data: {user: Me, accessToken, refreshToken}}`; `Me` = `{id, email, emailVerified, roles, authMethods, profile{nulls}, accountDeletion: null}`; register enqueues verification email (deferred with 5.2 — follow-up).

## Constraints

- Feature tier: clean slice — `internal/features/auth` (surface: Deps/Register/handlers) with `domain` (pure), `ports` (interfaces), `app` (services), `infra` (sqlc repository, Redis limiter).
- Platform pieces: `internal/platform/password` (argon2id PHC), `internal/platform/auth` (minimal keyring + EdDSA issuer; JWKS/verifier/guard land in 3.4), `internal/platform/clock` (injected clock — no `time.Now()` in services).
- Config mirrors the reference knobs: `AUTH_ACCESS_TOKEN_TTL_SECONDS=900`, `AUTH_REFRESH_TOKEN_TTL_SECONDS=2592000`, `AUTH_PASSWORD_MIN_LENGTH=10`, `AUTH_LOGIN_MAX_ATTEMPTS=10`, `AUTH_LOGIN_WINDOW_SECONDS=60`, `AUTH_LOGIN_BLOCK_SECONDS=900`, `AUTH_ISSUER`, `AUTH_AUDIENCE`, `AUTH_SIGNING_KEYS_JSON`, `AUTH_SIGNING_KEYS_JSON_BASE64`; env.example updated (knowledge gate enforces).
- Wire parity fix: `VALIDATION_FAILED` problems render title `Validation Failed` (backend's validation-only strategy); all other titles stay HTTP status text.
- Client context: user agent trimmed to 512 chars; IP from the socket peer (backend fastify default; proxy trust is a follow-up).
- IDs are UUIDv7 in Go; timestamps from the injected clock (utctime).
- Tokens: JWK parsing/signing via `github.com/lestrrat-go/jwx/v3` (locked stack).
- Errors are `httpx.ProblemError` values constructed by services and rendered once by the platform; codes added to `httpx/codes.go`.

Outcome: register and login are live and wire-validated — happy paths validate against the pinned snapshot (envelope, Me shape with nulls, `emailVerified` false, roles `[USER]`, authMethods `[PASSWORD]`), EdDSA access tokens carry the reference claims (`sub/sid/email_verified/roles/typ/iat/exp/jti`, kid header), refresh tokens are stored hashed, and sessions carry `userId:deviceId` active keys. Problem paths asserted: duplicate email 409, short password/invalid email 400 with `Validation Failed` + `errors[]`, wrong password and unknown email 401 (masked), suspended 403, deleted masked 401, and 10-failure blocking 429 with `Retry-After` that clears on success. Same-device login revokes the previous session and its refresh tokens. Unit tests cover the dummy-hash path, the limiter threshold/reset, password policy, and PHC compatibility with a real `@node-rs/argon2` hash. Coverage: 4 implemented / 30 allowlisted / 34 declared. Race-clean; `make verify` green except drift-until-commit (regenerated sqlc output, by design).

## Completion Notes

Boundary fixes the gates forced: the feature must not import `database/sql`, so the platform gained `db.Tx` (transaction seam), `db.ErrNoRows`, and the nullable args became `NULLIF(sqlc.arg(x), '')` so features pass plain strings; engine-coupled feature files (`auth.go`, `infra/repository.go`) are `!pg`-tagged until 7.1, mirroring `cmd/api` and `platform/db`. The contract harness now takes `t` per call (subtest-safe) and documents that the snapshot declares success schemas only — problem responses assert the platform shape, exact status, and declared codes. Other fixes: password parsing bound (`maxSegmentLength`) for gosec G115, unified register/login handlers, the reference kit's title strategy in `httpx` (`Validation Failed`).
