# 2.1 — Pin the backend-core-kit snapshot

- Status: completed
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 2.1
- Related ADRs: ADR-0002 (wire-contract parity with backend-core-kit)

## Objective

Vendor backend-core-kit's committed OpenAPI document into `contracts/backend.openapi.yaml` with `contracts/provenance.json` (source repository, commit, path, SHA-256), and ship the `gokit contract sync` / `gokit contract check` commands that create and verify the pin. Mirrors frontend-core-kit's `contracts:sync` machinery in Go.

## Constraints

- The snapshot is vendored byte-for-byte; provenance derives from the source working tree and refuses untracked or dirty source files (frontend-core-kit parity).
- Provenance schema (mirrors frontend-core-kit): `{schemaVersion, sourceRepository, sourceCommit, sourcePath, sha256}`.
- `contract check` is the digest gate: snapshot bytes must hash to the pinned digest; the document must be OpenAPI 3.x with a `paths` block.
- Landing `contracts/` removes it from the knowledge checker's planned-path allowlists (`plannedPaths`, `allowedMissingPaths`) — the allowlists shrink as phases ship.
- Source of truth: backend-core-kit HEAD `670d9bc6` (`docs/openapi/openapi.yaml`, sha256 `6ae079ad…`) at pinning time.

## Impact Areas

- API / contract: yes (pins the wire contract)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: no
- CI / release: yes (new `contract` step in the fast profile)

## Acceptance Criteria

1. `contracts/backend.openapi.yaml` and `contracts/provenance.json` committed; provenance hashes match `sha256sum` of the snapshot and record the backend commit.
2. `gokit contract sync --source <path>` is idempotent, validates OpenAPI 3.x, and refuses dirty/untracked sources with clear messages.
3. `gokit contract check` passes on the pinned tree and fails with the marker TODO on a tampered snapshot.
4. The `contract` step runs after `knowledge` in the fast profile.
5. knowledge checks pass without the `contracts/` allowlist entries; parser/unit tests for provenance derivation and source validation.

## Verification

```bash
go run ./tools/gokit contract sync --source ~/workspace/devs/core/backend-core-kit/docs/openapi/openapi.yaml
go run ./tools/gokit contract check
sha256sum contracts/backend.openapi.yaml
make verify
```

Outcome: pinned `contracts/backend.openapi.yaml` from backend-core-kit `670d9bc62e6a` (sha256 `6ae079adec93…`), recorded in `provenance.json` (repository `git@github.com:fikrilal/backend-core-kit.git`). `gokit contract check` passes; the `contract` step runs after `knowledge` in the fast profile. Tamper detection verified in tests via `CONTRACT_SNAPSHOT_PATH` (marker: "snapshot digest does not match provenance"). `make verify` green.

## Completion Notes

`gokit contract sync --source <path>` derives provenance from the source repository (remote URL, HEAD commit, repo-relative path, SHA-256) and refuses untracked or dirty sources; artifacts are written atomically with repository-standard permissions. `gokit contract check` enforces the digest and the OpenAPI 3.x `paths` shape. Both read `CONTRACT_SNAPSHOT_PATH` / `CONTRACT_PROVENANCE_PATH` overrides (used by 2.5's gate honesty). The knowledge checker's `contracts/` allowlist entries were removed — the shrinking allowlists did their job. Gate-driven fixes: four justified `gosec` nolints (operator-provided source path, env-overridable pinned paths, artifact directory permissions) and 0644 artifact permissions in the atomic writer.
