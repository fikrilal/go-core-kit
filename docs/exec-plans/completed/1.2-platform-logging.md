# 1.2 — Platform Logging

- Status: active
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 1.2
- Related ADRs: ADR-0009 (observability: slog and OpenTelemetry)

## Objective

Implement `internal/platform/logging`: a structured `slog` logger honoring `LOG_LEVEL` and `LOG_FORMAT`, sensitive-attribute redaction, and canonical correlation field keys.

## Constraints

- stdlib only (`log/slog`); no third-party logger.
- May import `internal/platform/config`; `internal/platform` must not import features (depguard).
- JSON output is the production format; text is available for local development.
- Redaction list stays small and explicit.

## Impact Areas

- API / contract: no
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no (consumes `LogLevel` / `LogFormat` only)
- Observability: yes
- CI / release: no

## Acceptance Criteria

1. `logging.New(level, format, w)` builds a `*slog.Logger` honoring the configured level and format.
2. Sensitive attributes — `password`, `token`/`access_token`/`refresh_token`/`id_token`, `authorization`, `cookie`, `secret`, `api_key`, `private_key` — are replaced with `[REDACTED]`, case-insensitively, including nested groups; non-sensitive attributes pass through.
3. `FieldRequestID` / `FieldTraceID` constants define the correlation keys used across platform and features.
4. Tests cover JSON and text output, level filtering, redaction (including a nested group), and bound correlation fields.
5. `make verify` green.

## Steps

## Decision Log

- 2026-10-10: Redaction is key-based via `slog`'s `ReplaceAttr` with a small explicit key list; pino-style path redaction has no direct `slog` equivalent, and over-broad substring matching risks hiding useful logs.
- 2026-10-10: `New` takes `LogLevel` / `LogFormat` (not the full `Config`) — minimal inputs, decoupled from unrelated config surface.
