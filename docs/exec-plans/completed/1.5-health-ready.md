# 1.5 — Health and Readiness Probes

- Status: active
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 1.5
- Related ADRs: ADR-0003 (stdlib HTTP), ADR-0009 (observability)

## Objective

Add `internal/platform/health`: `GET /health` (liveness) and `GET /ready` (readiness with injectable dependency checks), plus the `httpx.SkipAccessLog` mechanism so probes stay out of the request log.

## Constraints

- Probes are a documented envelope exception (like backend-core-kit): bodies are `{"status": …}`, never `{data: …}`.
- No side effects from checks; failures log a warning and never leak error internals into the response body.
- Checks are injected — Redis ping (1.6) and DB ping (1.9) plug in later without API changes.
- `X-Request-Id` still applies to probe responses (contract: every response).

## Impact Areas

- API / contract: yes (documented exception endpoints)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: yes (probes excluded from access log)
- CI / release: no

## Acceptance Criteria

1. `GET /health` → 200 `{"status":"ok"}`, `Content-Type: application/json`, request id echoed.
2. `GET /ready` → 200 `{"status":"ok"}` when all checks pass; 503 `{"status":"unavailable","checks":{name:"unavailable"}}` otherwise.
3. Failing checks are logged at warn with the underlying error; the response never contains error internals.
4. Probe requests produce no access-log lines (via `httpx.SkipAccessLog`).
5. Tests cover all of the above; `make verify` green.
