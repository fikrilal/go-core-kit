# 2.4 — Operation allowlist, coverage, and spec lint

- Status: completed
- Owner: Core kit maintainers
- Risk: medium
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 2.4
- Related ADRs: ADR-0002 (parity), ADR-0010 (verify gate)

## Objective

Make operation coverage mechanical: route registrations carry their contract operation id, a coverage test asserts (implemented ∪ allowlisted) equals the snapshot exactly, and `vacuum` lints the pinned spec with a ruleset mirrored from backend-core-kit's Spectral config.

## Constraints

- Registrations carry `(method, path, operationId)`; the router records them and exposes the surface. `health.Register` updates accordingly; runtime dispatch patterns keep today's ServeMux semantics (no 405 behavior change in this task).
- `contracts/allowlist.yaml` lists every unimplemented operation grouped by phase, with comments; it must shrink as phases land and is never a dumping ground for mistakes.
- Coverage invariants (Go test in `cmd/api`, runs inside `go test ./...` → `make verify`):
  - every registered operation id exists in the snapshot;
  - every snapshot operation is registered or allowlisted;
  - registered ∩ allowlisted = ∅;
  - per operation id, registered method+path equal the snapshot's method+path;
  - allowlist ids exist in the snapshot (typo guard).
- `vacuum` v0.33.0 pinned in the Makefile and installed by `make tools`; ruleset `contracts/vacuum.yaml` mirrors backend-core-kit's `.spectral.yaml` (metadata-only rules; operationId, tags, and `x-error-codes` required — error severity).
- `gokit contract check` grows to parse the allowlist (ids unique, all present in the snapshot).
- `contract-lint` becomes a full-profile step (vacuum needs the tool; fast profile stays tool-light).

## Impact Areas

- API / contract: yes (the coverage proof)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: no
- CI / release: yes (full profile gains `contract-lint`)

## Acceptance Criteria

1. Snapshot operations: 34; registered: `health.get`, `ready.get`; allowlist: the remaining 32 grouped by phase.
2. Coverage test fails on: a missing allowlist entry, a phantom registration, a method/path mismatch, and an allowlist typo (verified by temporary injections during development).
3. `vacuum lint --fail-severity warn` passes on the pinned snapshot with the mirrored ruleset; the step is wired into the full profile.
4. `doctor` verifies `vacuum` against the pin.
5. `make verify` green.

## Decision Log

- 2026-10-10: Operation ids live on registrations (code is the source of truth for "implemented"); a separate hand-maintained inventory could lie — the route table cannot.
- 2026-10-10: Coverage runs as a Go test, not a gokit check, because it needs the composed route surface (cmd/api owns composition).
- 2026-10-10: vacuum ruleset mirrors backend's Spectral config so the lint bar is identical; the snapshot must pass what its origin passes.
- 2026-10-10: vacuum gates on `--fail-severity error` — the mirrored ruleset's three contract rules are error-level, matching the origin's enforced bar; the base Spectral set's 156 warnings are informational.
- 2026-10-10: Idempotency scope switches from the route pattern to the operation id (stable under path changes).

## Completion Notes

Registrations carry `httpx.Operation{Method, Path, ID}`; the router records them and `Operations()` exposes the surface. The idempotency scope is now the operation id. httpx tests use a `testOp` helper. `contracts/allowlist.yaml` is a flat list with comment groups; `contracts.ParseAllowlist` is shared by gokit and the coverage test. Acceptance criterion 2 was exercised by direct injection during development (unknown operation, duplicate, and missing entries each fail with their markers).

## Verification

```bash
go test ./cmd/api/... -run Coverage -count=1 -v
go run ./tools/gokit verify --profile full
make verify
```

Outcome: `contract check` reports "32 pending, 2 implemented, 34 declared". The coverage test enforces all five invariants in `go test` (fast and full profiles). Injection proof: a doctored snapshot with `gates.honesty.fake` inserted into `paths` fails with the marker "snapshot operations missing from the allowlist and not implemented: [gates.honesty.fake]"; allowlist typos and duplicates are caught by gokit tests via `CONTRACT_ALLOWLIST_PATH`. vacuum 0.33.0 lints the pinned snapshot with 0 errors and used as the `contract-lint` full-profile step; `doctor` reports all four pins. `make verify` green (full profile ≈4.6s).
