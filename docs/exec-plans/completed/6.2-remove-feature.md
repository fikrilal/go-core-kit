# 6.2 — `remove feature`

## Objective

One command removes a feature and unwires everything the scaffold wired, so the
tree is left as if the feature had never been scaffolded — the inverse of 6.1
and the reason its wiring is marker-delimited text.

## Design

`gokit remove feature --name <name>`:

1. **Unwire first.** Drops the feature's import and `Register` call from
   `cmd/api/server.go`, leaving the `// gokit:feature-registrations` marker for
   the next scaffold. A feature that is not registered refuses here, before
   anything is deleted.
2. **Return its operations to the allowlist.** Scans the feature's Go files for
   route ids (`ID: "<operation>"`) and lists any that are missing from
   `contracts/allowlist.yaml` again — removal un-implements them, and the
   coverage test compares the snapshot against the allowlist plus the routes, so
   the allowlist must grow back by exactly what the feature implemented.
3. **Delete its files.** The feature directory, the per-feature contract tests
   under `cmd/api`, and `db/queries/common/<name>.sql`.

Order matters: every text edit completes before the first deletion, so a refusal
(unknown name, missing directory, unregistered feature) leaves all files in
place. Removal never touches migrations — the scaffold writes none — and the
generated sqlc output is `make generate`'s job, which the command prints.

## Acceptance checks

1. Scaffold a feature plus an endpoint, then remove it: no import, no `Register`
   call, the marker intact, the directory deleted, and the operation listed as
   unimplemented in the allowlist again.
2. Refusals are side-effect free: unknown name, malformed name, and a feature
   whose registration is missing all leave the tree untouched.
3. `make verify` passes after a scaffold → remove cycle once generation runs.

## Outcome — landed 2026-10-15

`gokit remove feature --name <name>` implements the three steps above, and its
tests cover the full cycle (scaffold feature + endpoint → remove → assert the
composition root, the allowlist, the directory, the contract test, and the query
are all back to their pre-scaffold state), the refusal set, and the
leave-in-place guarantee when a feature is not wired.

Verification: `go test ./...` green, `golangci-lint run` 0 issues, `make verify`
full profile passed.

## Notes

- The allowlist entries are appended without a phase comment. The file's grouping
  comments describe how the operations were landed, not how they are removed; a
  reviewer re-grouping them by hand is cheap and keeps the intent readable.
- Removing a feature that another feature imports is refused only indirectly (the
  tree stops compiling). Cross-feature imports are allowlisted per pair anyway, so
  the scaffold cannot create one; no extra guard was added for a case the kit
  forbids by construction.
