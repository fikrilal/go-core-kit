# 1.9a — DB Engine and Migrations

- Status: completed
- Owner: Core kit maintainers
- Risk: medium
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 1.9 (part a; part b is the sqlc pipeline)
- Related ADRs: ADR-0004 (SQLite first, build-time Postgres swap), ADR-0005 (sqlc, goose, portable subset)

## Objective

Ship the SQLite engine in `internal/platform/db` — open with platform pragmas and write policy, `Ping`/`Close`, `InTx`, and the embedded goose migration runner — plus the per-engine migration sets at `db/migrations`. Proven by tests against a temporary database.

## Constraints

- Drivers: `modernc.org/sqlite` (pure Go, static builds) and `github.com/pressly/goose/v3` only.
- Migrations live at `db/migrations/{sqlite,pg}`; a tiny `migrations` package at `db/migrations/` embeds both sets (Go `embed` cannot reference parent directories, and keeping the `.go` file outside the SQL dirs keeps sqlc's schema parsing clean).
- The engine file is build-tagged `!pg` from day one — the seam is reserved, the Postgres runtime variant lands with task 7.1.
- Pragmas and the write policy are set through the DSN (`_pragma=…`, `_txlock=immediate`), not hand-rolled connection code.
- The `users` table is the seam's real payload (minimal columns). Auth (task 3.1) extends the schema with further migrations; nothing is a placeholder.

## Impact Areas

- API / contract: no
- DB / migrations: yes
- Auth / session: no (schema skeleton only)
- Queue / jobs: no
- Config / secrets: no (`DATABASE_PATH` exists)
- Observability: no (goose's own logging is silenced; structured logging stays ours)
- CI / release: no

## Acceptance Criteria

1. `Open` applies WAL + `busy_timeout(5000)` + `foreign_keys(1)` + `synchronous(NORMAL)` and uses `_txlock=immediate`; verified by reading the pragmas back.
2. Single-connection policy (`SetMaxOpenConns(1)`) keeps SQLite's single-writer model explicit.
3. `Migrate` applies the embedded goose set idempotently and creates `users`; both engines' sets exist with matching semantics.
4. `InTx` commits on success, rolls back on callback error, and returns the callback's error unchanged.
5. `Ping` and `Close` wrap driver errors; timestamps round-trip as `time.Time` (RFC3339 on SQLite).
6. Tests cover all of the above; `make verify` green.

## Decision Log

- 2026-10-10: `_txlock=immediate` in the DSN replaces a manual `BEGIN IMMEDIATE`; `busy_timeout(5000)` is the driver-level retry window (the proposal's "busy retry").
- 2026-10-10: `Database.SQL()` exposes the `database/sql` handle — generated queries (`sqlc` database/sql output) and goose both build on it; the Postgres variant must fit the same surface (revisited in 7.1).
- 2026-10-10: Timestamps are stored as RFC3339 `TEXT` on SQLite and `TIMESTAMPTZ` on Postgres; sqlc column overrides normalize both to `time.Time` (lands with 1.9b).
- 2026-10-10: goose's logger is silenced so migration output goes through the platform logger at the composition root.

## Completion Notes

Shipped the SQLite engine (`Open` with DSN pragmas + `_txlock=immediate`, single-connection policy, `InTx`, goose runner with silenced logger), the embedded migration sets (`db/migrations` + `0001_init.sql` for sqlite and pg), and the `utctime.Time` value type. Two discoveries shaped the result: (1) gofumpt enforces a blank comment line before `//go:embed` — the fmt gate caught a wrong "fix" immediately; (2) `modernc.org/sqlite` returns TEXT columns as `string`, so plain `time.Time` scanning is impossible — `utctime.Time` (RFC3339 on the wire, UTC-normalized in Go) is the answer, and it is exactly what the sqlc column overrides will map both engines to in 1.9b. Tests: pragmas verified by reading them back, idempotent migrate + insert/select roundtrip, commit/rollback with sentinel error, ping-after-close.
