# 2.5 — Gate-honesty meta-test

- Status: completed
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 2.5
- Related ADRs: ADR-0010 (verify gate)

## Objective

Prove the gates are real: `gokit gates honesty` injects a stale snapshot and a forbidden import into the tree, runs the actual gates, and asserts both fail with their expected markers. Mirrors backend-core-kit's `scripts/gates-honesty.ts`.

## Constraints

- Each scenario runs the real gate as a subprocess (no reimplementation): `gokit contract check` (digest), the `cmd/api` coverage test (snapshot inventory), and `golangci-lint` (depguard).
- Snapshot injection uses the `CONTRACT_SNAPSHOT_PATH` override — same mechanism the suite and coverage test read.
- Forbidden-import injection writes a temporary package under `internal/platform/httpx/__gates__/` importing a confined DB driver, then removes it in all paths (including failure); the tree must be byte-clean afterwards.
- Assertions require both a non-zero exit and the expected marker substring; a gate that unexpectedly succeeds fails the meta-test ("gate may be ineffective").
- `gates-honesty` becomes a full-profile step. Scenario B requires golangci-lint (already a full-profile prerequisite); scenario A requires only the built binary.

## Impact Areas

- API / contract: yes (verifies the digest + coverage gates)
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: no
- Observability: no
- CI / release: yes (full profile gains `gates-honesty`)

## Acceptance Criteria

1. Scenario A (stale snapshot): a doctored snapshot fails the digest gate with its marker, and separately fails the coverage gate with its marker.
2. Scenario B (forbidden import): the injected driver import fails `golangci-lint` with the depguard marker, and the temporary package is removed whether the scenario passes or fails.
3. Markers are constants shared between the gates and the meta-test where possible; assertion messages name the gate and the expected marker.
4. `gokit gates honesty` exits non-zero when any gate under test unexpectedly passes.
5. `make verify` green with the step wired into the full profile.

## Steps

- [x] `gates.go`: scenario runner (subprocess + marker assertions) + cleanup guarantees
- [x] Scenario A: digest gate (contract check, env override) + coverage gate (`go test` with env override)
- [x] Scenario B: depguard violation fixture + lint run
- [x] Command parser/usage updates + `gates-honesty` step in the full profile
- [x] `make verify`; confirm a clean worktree afterwards

## Decision Log

- 2026-10-10: Subprocess execution of the real gates (backend-core-kit parity) — reimplementing gate logic in the meta-test would test the copy, not the gate.
- 2026-10-10: Scenario B targets the features-scoped driver rule — that is the boundary rule drivers actually violate; the fixture lives where the rule applies.
- 2026-10-10: The tree must be clean after every run; fixtures live only for the duration of a scenario.
- 2026-10-10: The violation fixture uses a normal directory name — the Go toolchain ignores `_`-prefixed directories, so backend-core-kit's `__gates__` convention does not port.

## Completion Notes

Injection anchors: the digest scenario appends a comment to a snapshot copy (the shape checks are regex-level, so the digest mismatch is what fires); the coverage scenario inserts a fake operation before the snapshot's `info:` key. Cleanup removes the fixture file, the violation directory, and the (now empty) `internal/features` root in a defer. Markers are constants shared with the gates' messages.

## Verification

```bash
go run ./tools/gokit gates honesty
git status --porcelain   # clean
make verify
```

Outcome: `gokit gates honesty` proves all three scenarios live — a tampered snapshot fails the digest gate ("snapshot digest does not match provenance"), a doctored snapshot with an undeclared operation fails the coverage gate ("missing from the allowlist and not implemented"), and an injected driver import fails depguard ("features must not import database drivers"). No fixture leftovers after the run; `expectGateFailure` unit-tested for the ineffective-gate, missing-marker, and passing cases. The step runs in the full profile (≈1.7s) and `make verify` is green (full ≈6.4s).
