# 5.3 — Push jobs + FCM adapter

- Status: completed
- Owner: Core kit maintainers
- Risk: medium
- Date: 2026-10-13
- Roadmap: `docs/exec-plans/roadmap.md` Phase 5
- Related ADRs: ADR-0006 (asynq), ADR-0007 (config)

## Objective

Land the push lane: an FCM HTTP v1 adapter behind a `platform/push` sender port, the `push.send` job with the reference's session-state machine, and the credential-derived enablement that replaces 4.3's `PUSH_ENABLED` placeholder. Allowlist untouched.

## Ground truth (read from the reference before writing code)

- Queue/job/payload (`libs/platform/push/push.job.ts`): queue `push`, job `push.send`, payload `{sessionId, notification?{title?,body?}, data?{string:string}, requestedAt}` — **session-scoped**, not token-scoped.
- Provider contract (`push.types.ts`): `sendToToken({token, notification?, data?}) → {messageId}`; failures are `PushSendError` with a `code` enum (`push/not-configured`, `push/invalid-token`, `push/send-failed`), an optional provider code, and a **retryable** flag. Disabled provider throws not-configured, non-retryable.
- Enablement (`env.schema.ts`): `PUSH_PROVIDER=FCM` plus `FCM_PROJECT_ID` and one credential source — `FCM_SERVICE_ACCOUNT_JSON`, `..._BASE64`, `..._PATH`, or `FCM_USE_APPLICATION_DEFAULT`.
- Worker handler (`apps/worker/src/jobs/push.worker.ts`), all skips are **successful** outcomes:
  1. session missing → `skipped/session_not_found`; revoked → `skipped/session_revoked`; expired → `skipped/session_expired`; user not `ACTIVE` → `skipped/user_inactive`; no `pushToken` → `skipped/no_token`;
  2. else send; success → `sent` with `messageId`;
  3. on a **non-retryable invalid-token** failure: clear the session's token with a **compare-and-set** (`updateMany where id AND pushToken = token`) stamping `pushTokenUpdatedAt`/`pushTokenRevokedAt`, then return `skipped/invalid_token` with the provider code; any other failure rethrows so the retry policy applies.

## Constraints

- FCM via **stdlib + jwx** (already a dependency): service-account JSON → RS256-signed JWT → OAuth2 token exchange at `https://oauth2.googleapis.com/token`, cached until shortly before expiry; then `POST https://fcm.googleapis.com/v1/projects/<id>/messages:send`. No new module dependencies.
- `PUSH_ENABLED` is replaced by credential-derived enablement: `cmd/api`'s 4.3 gate and the worker both ask the same `push.Options.Enabled()`. Recorded as the promised 5.3 swap.
- The sender port lives in `internal/features/me/ports` (the feature that owns push tokens) with the platform client satisfying it; the worker composes through `me.NewPushJobs(...)` at the feature root, mirroring 5.2.
- Queries: one session-for-push read (session id, user status, revoked/expiry, push token) and one compare-and-set clear. The CAS predicate is what prevents a stale worker from clearing a freshly rotated token.
- Unknown job names on the `push` queue error out, mirroring the reference.

## Impact Areas

- API / contract: no operations (provider enablement changes 4.3's gate source only)
- DB / migrations: no schema change; two new queries
- Auth / session: session/token state read and CAS-clear on the worker side
- Config / secrets: `PUSH_PROVIDER`, `FCM_PROJECT_ID`, four credential knobs; `PUSH_ENABLED` retired (+ `env.example`)
- Observability: handler logs carry session id, outcome, and provider code
- CI / release: worker consumes the `push` queue

## Acceptance Criteria

1. The FCM client exchanges a service-account JWT for an access token (cached across sends) and posts to the v1 endpoint with the bearer token, returning `name`'s message id.
2. Failure mapping: unregistered/invalid tokens → non-retryable `invalid-token` with the provider code; 5xx/429 → retryable `send-failed`; unconfigured provider → non-retryable `not-configured`.
3. The handler returns every skip as success without sending; sends once when the session is live and holds a token.
4. An invalid-token failure clears the session's token **only when it still matches the sent token**, and returns `skipped/invalid_token`; any other failure propagates.
5. 4.3's gate now follows FCM credentials: the upsert returns 501 when they are absent, 204 when present (existing tests updated).
6. `make verify` green; generated code committed.

## Decision Log

- 2026-10-13: Service-account JWT via jwx with a cached access token — the reference's ADC path has no stdlib equivalent, so `FCM_USE_APPLICATION_DEFAULT` stays unported (recorded).
- 2026-10-13: The compare-and-set clear is the invariant that makes invalid-token cleanup safe against concurrent registrations.
- 2026-10-13: Payloads are session-scoped (reference), so the handler resolves the token itself instead of trusting the producer.

Outcome: the push lane is live. `internal/platform/push` sends FCM HTTP v1 notifications with a service-account assertion exchanged for a cached access token (stdlib + jwx, no new dependencies), maps failures onto the reference's classes (invalid-token non-retryable, 429/5xx retryable, not-configured), and carries the session-scoped payload. The 4.3 provider gate now follows FCM credentials instead of the retired `PUSH_ENABLED` placeholder. The `push.send` handler resolves the session and skips missing/revoked/expired/inactive/no-token cases as successes, sends otherwise, and on a non-retryable invalid-token failure clears the stored token only when it still matches what was sent. `cmd/worker` registers the handler on the `push` queue when credentials are present.

Verification: push client tests cover token caching, bearer/payload shape against a fake Google (the token endpoint asserts a signed 3-part assertion), base64 credentials, the full failure-mapping table, and the disabled client. Handler tests cover the send path, all five skips, the invalid-token clear with the provider code, and failure propagation without clears. The worker test asserts both feature handler sets register from configuration. `golangci-lint run` 0 issues; both lanes build; `make verify` full profile passed on a scratch copy with the regenerated artifacts committed (the live tree's `drift` is red by design until commit).

## Completion Notes

Deviations and discoveries: the reference's three credential knobs (`FCM_SERVICE_ACCOUNT_JSON`, `..._BASE64`, `..._PATH`) collapse into one autodetected `FCM_SERVICE_ACCOUNT_JSON` (raw JSON, base64 of it, or a path), and `FCM_USE_APPLICATION_DEFAULT` stays unported because ADC has no stdlib equivalent. `PUSH_ENABLED` is gone: the API gate and the worker both ask `push.Options.Enabled()`, so the 4.3 fixtures now supply credentials instead of a boolean. `me.NewPushJobs` keeps the composition root free of feature internals, and the CAS clear is what protects a concurrently rotated token.
