# 3.1 — Auth schema and migrations (SQLite first)

- Status: completed
- Owner: Core kit maintainers
- Risk: medium
- Date: 2026-10-11
- Roadmap: `docs/exec-plans/roadmap.md` task 3.1
- Related ADRs: ADR-0004 (SQLite first), ADR-0005 (sqlc + goose + portable subset)

## Objective

Land the auth data model — `users` extensions, `password_credentials`, `sessions`, `refresh_tokens` — in the SQLite migration set, mirroring backend-core-kit's Prisma model semantics, with the sqlc surface and drift gate green. Fold in the three non-blocking nits from the Phase 2 review.

## Reference (backend-core-kit)

- `User`: id, email (unique), emailVerifiedAt, role (USER/ADMIN), status (ACTIVE/SUSPENDED/DELETED), suspendedAt/Reason, timestamps; indexes on deletion fields (deferred here to 4.5).
- `PasswordCredential`: userId (PK, cascade), passwordHash, timestamps.
- `Session`: id, userId, deviceId/deviceName, push fields, ip, userAgent, activeKey (unique — one active session per (user, device)), lastSeenAt, expiresAt, revokedAt, timestamps; indexes on userId/deviceId/revokedAt/pushTokenRevokedAt.
- `RefreshToken`: id, tokenHash (unique), expiresAt, revokedAt, sessionId, replacedById (unique self-relation for rotation), timestamps; indexes on sessionId/revokedAt.

## Constraints

- SQLite translation: `TEXT` ids (UUIDv7 in Go), `TEXT` timestamps (utctime format), enums via `CHECK (... IN (...))`.
- Migration is additive (`0002_auth.sql`): `0001_init.sql` stays untouched; deletion columns land with 4.5, email/reset token tables with 3.6/3.7.
- Down migration must be real: SQLite cannot drop CHECK-constrained columns — rebuild `users` in Down.
- sqlc: per-column timestamp overrides for every new timestamp column; regenerate + drift green.
- Postgres set untouched (phase 7.1 owns the pg lane).
- Phase 2 review nits folded in: `ParseAllowlist` strips inline comments; `snapshotOperationIDs` strips quotes; the gate-honesty fixture only removes `internal/features` when it created it.
