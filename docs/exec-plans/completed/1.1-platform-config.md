# 1.1 — Platform Config

- Status: active
- Owner: Core kit maintainers
- Risk: low
- Date: 2026-10-10
- Roadmap: `docs/exec-plans/roadmap.md` task 1.1
- Related ADRs: ADR-0007 (config from env with fail-fast invariants)

## Objective

Implement `internal/platform/config`: typed environment parsing with defaults, fail-fast validation with invariants, and `env.example` documenting development values.

## Constraints

- stdlib + `github.com/caarlos0/env/v11` only; no other dependencies.
- `internal/platform` must not import features (enforced by depguard).
- Secrets never in git; example values only.
- Scope: app env, HTTP port, database path, Redis URL, log level, log format. Module-specific keys (auth, storage, email, push, OTel) land with their modules.

## Impact Areas

- API / contract: no
- DB / migrations: no (`DATABASE_PATH` key defined only)
- Auth / session: no
- Queue / jobs: no
- Config / secrets: yes
- Observability: yes (`LOG_LEVEL` / `LOG_FORMAT` keys)
- CI / release: no

## Acceptance Criteria

1. `config.Load()` parses env, applies defaults, and validates: enum values, port range, and the production invariant (structured logs in prod).
2. Missing `DATABASE_PATH` or `REDIS_URL` fails with a clear, wrapped error.
3. `env.example` documents all keys with development values.
4. Tests cover defaults, required keys, parse errors, enum violations, and the prod invariant.
5. `make verify` green (strict linters included).
