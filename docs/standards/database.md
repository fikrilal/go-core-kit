# database

Two engines, one shape: the SQLite and Postgres lanes are selected by build tag,
and the code above `internal/platform/db` does not know which one it runs on.

## Where SQL lives

SQL lives in the repository and in `db/queries/**`; handlers and services never
build queries. `internal/db/gen` is generated by sqlc from the portable query set
in `db/queries/common/`, which sqlc transpiles per engine (placeholders included),
and the generated code is committed and drift-checked: `make generate` followed by
`gokit drift check` fails when the tree and the queries disagree.

## Driver isolation

Database drivers are importable only inside `internal/platform/db` and
`internal/db/gen`; the boundary gate enforces it. A feature that wants a
connection asks for the `*db.Database` the composition root hands it.

## Transactions

Writes that touch more than one statement go through `InTx`. On the pg lane the
transaction is serializable and a serialization conflict is retried with a bounded,
jittered backoff — which means **a caller's closure may run more than once**, so it
must not write anything outside the transaction it is given. The finalize job is
the worked example: its audit row and its deletes live inside the same closure.

## Engine parity

Both lanes generate the same Go types: `sqlc.yaml` overrides every nullable
timestamp column to `utctime.Time` on both engines, so a repository that reads
`row.ExpiresAt.Time` compiles and behaves the same way either way. The schema
inventory test holds the two migration trees to the same table and column names.

## Portable hand-written SQL

Where SQL is assembled by hand, it is written once and passed through `db.Rebind`,
which is the lane's placeholder translator. Generated queries do not need it — sqlc
already emits the lane's style — and the translation is literal-blind, so a hand-
written query must keep `?` out of everything but placeholders.

## Migrations

Migrations are goose files per engine under `db/migrations/{sqlite,pg}`, applied in
process at API startup. The worker deliberately does not migrate: it assumes the
schema the API applied, so a fresh box starts the API first.

## Time

Time in services and repositories comes from the injected clock; `time.Now()` is a
lint failure in feature code. Values cross the database boundary through
`utctime.Time`, which stores a fixed-width UTC text form so ordering and cursor
comparisons are exact.

## Moving data between engines

`gokit db export --out <file>` writes the compiled lane's tables as JSON lines: a
versioned header per table, then one line per row with values in their stored text
form (null stays null). `gokit db import --in <file>` applies it, one transaction
per table, in dependency order; it refuses a target that already holds rows unless
`--replace` is passed, and `--dry-run` reports the row counts without writing.

There is no `--lane` flag, because one binary is one engine: the SQLite build
exports, the pg build imports, and a cross-engine move is two invocations. The table
list in `tools/gokit/dbmove.go` is the kit's schema in dependency order — a future
migration adds its table there, since portable table discovery would have to name an
engine.
